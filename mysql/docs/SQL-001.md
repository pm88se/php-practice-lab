# SQL-001 — Atomic Money Transfer

**EAV: ~20–30 minutes** · MySQL 8.4 / InnoDB · PHP PDO · **Base**

## Scenario

A SaaS application keeps balances for three internal accounts. An operation
moves 2,500 cents from Alice's account to Bob's. If ANY part fails, neither
account's balance may change.

## Your task

Implement ONLY `Sql001MoneyTransfer::transfer()` in
`mysql/src/Sql001MoneyTransfer.php`.

Arguments: `PDO $pdo, int $fromId, int $toId, int $amountCents`.

Requirements:
- Positive amount, different source and destination IDs.
- Both accounts must exist; insufficient balance is an error.
- On success, decrease the source balance and increase the destination balance
  **atomically**, preserving the total.
- On any failure, leave **both balances unchanged** and propagate an exception.
- Use actual SQL queries with prepared statements and PDO transaction methods.
  Use the **supplied PDO**, not a new database connection.
- Do not solve this with in-memory PHP arrays.
- `InvalidArgumentException` for invalid amount or identical IDs;
  `RuntimeException` for missing account or insufficient funds.
- Balances are stored in **integer cents**, not PHP floats.

Focus: `BEGIN` / `COMMIT` / `ROLLBACK`, consistent updates, checking
the outcome of SQL statements. Do not add framework abstractions or build a
transaction manager. This is **not** yet a concurrent-transfer exercise:
`SELECT ... FOR UPDATE`, race conditions, deadlocks and retries are studied
in SQL-002–004.

## Test locally

After merging the setup PR:

```bash
# With your local MySQL container already running:
php mysql/tests/run.php
```

The setup PR intentionally has red SQL-001 tests because `transfer()`
contains a stub. Existing PHP Core tests remain independent.

The SQL runner resets the disposable `accounts` fixture; never point it
at a database containing important data.

## Expected initial state

| Account | ID | Balance |
|---|---:|---:|
| Alice | 1 | 10000 cents |
| Bob | 2 | 5000 cents |
| Carol | 3 | 0 cents |

Run `php mysql/bin/reset.php` to manually reset balances.

## Acceptance criteria

1. Successful transfer of 2500 cents from account 1 to 2 produces 7500 / 7500.
2. Insufficient funds changes nothing.
3. Missing destination changes nothing, even if debit happened first.
4. Zero/negative amount and same-account transfer are rejected.
5. Failure does not poison the PDO connection: a subsequent valid transfer works.
