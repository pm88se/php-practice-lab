# SQL-003 — Idempotent Payment Webhook

**EAV: 20–30 minutes** · Base · PHP PDO + MySQL/InnoDB

## Business scenario

A payment provider sends an event such as `payment-001` to notify our SaaS
that a payment of 2500 cents has succeeded. The provider retries the same
webhook if delivery acknowledgment was lost. We must credit the account
**only once**. Different event IDs represent different payments.

## Implement

`Sql003PaymentWebhook::apply(PDO $pdo, string $eventId, int $accountId, int $amountCents): bool`
in `mysql/src/Sql003PaymentWebhook.php`.

- Return **true** if this is a new event and its amount is credited.
- Return **false** if the event ID was already processed, without crediting
  anything again (even if the duplicate payload has changed).
- Reject empty event IDs and amounts <= 0 with `InvalidArgumentException`.
- Reject nonexistent target accounts with `RuntimeException`.
- Record the event ID in `payment_events` (unique primary key) and credit the
  `accounts.balance_cents` in **one transaction**.
- Roll back any incomplete operation on failure.
- Reuse the supplied PDO; SQL is written directly in PHP.
- Use the database uniqueness guarantee rather than an unsafe
  `SELECT`-then-`INSERT` check as your only duplicate protection.
- No frameworks, queues, provider SDKs, retries or extra layers.

## Example

Balance: 10000 cents. First delivery `payment-001` with amount 2500:
balance -> 12500, return true. Same event delivered again: unchanged,
return false. New `payment-002` with amount 500: balance -> 13000.
