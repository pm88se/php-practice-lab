# SQL-004 — NOWAIT and SKIP LOCKED

**EAV: 25–35 minutes** · Base/Deep transition · MySQL 8.4 / InnoDB / PDO

## Problem

Workers take pending rows from a small jobs table. One worker is already
holding a row lock on job 1. A second worker must either refuse to wait for
that particular job (**NOWAIT**) or find another free job (**SKIP LOCKED**).

## Schema (also in implementation comments)

```sql
CREATE TABLE jobs (
    id BIGINT UNSIGNED PRIMARY KEY,
    payload VARCHAR(100) NOT NULL,
    status VARCHAR(20) NOT NULL
) ENGINE=InnoDB;
```

Seeded jobs: (1, email-A, pending), (2, email-B, pending),
(3, email-C, pending).

## Your work

Write **all locking and transactional SQL yourself** in
`mysql/src/Sql004JobLocks.php`:

- `holdJob(PDO $pdo, int $jobId): bool`: start transaction, lock a row
  exclusively, retain the transaction; return false and close it if missing.
- `releaseJob(PDO $pdo): void`: finish the held transaction.
- `claimNowait(PDO $pdo, int $jobId): bool`: start transaction, attempt
  to claim a pending job using `NOWAIT`, update its status and commit.
  A conflicting lock must raise MySQL error **3572**; rollback and rethrow.
- `claimNext(PDO $pdo): ?int`: start transaction, choose the lowest-ID
  pending unlocked job using `SKIP LOCKED`, update it to processing,
  commit and return its ID. Return null if no unlocked pending job exists.

Unlike an ordinary SELECT, locking reads can wait for incompatible row
locks. NOWAIT fails rather than waiting; SKIP LOCKED excludes locked
rows from the result set, which is useful for queue-like consumers.

## What the tests reveal

- Job 1 held by A: claiming it with NOWAIT on B fails with error 3572.
- B's SKIP LOCKED read returns job 2 instead, then job 3.
- With only locked pending job 1 remaining, claimNext returns null.
- Releasing A's lock allows B to claim job 1.
- Already processing jobs aren't claimed a second time.

The test harness creates independent PDO connections and fixtures; your
implementation controls **every transaction and each locking SQL statement**.
No sleeps, threads, artificial callbacks, or frameworks.
