# PHP-006 — Long-Running Worker: State Isolation & Failure Recovery

- **Engineering problem:** Reliability / mutable state leakage across tasks
- **Focus:** `try/catch/finally`, `Throwable`, explicit request-scoped context
- **Level:** Base → Deep
- **EAV:** 25–35 minutes
- **Setup branch:** `setup/PHP-006`
- **Implementation branch:** `drill/PHP-006` (after merging setup)

## Production scenario

A PHP CLI worker handles many jobs in the **same process**. Each job has an ID, maybe a tenant ID, and handler-created temporary values. A failed handler must not leave a tenant ID, token or other state visible to the next job.

Build a tiny synchronous job runner with an explicit context and predictable failure results. Do not add Laravel, retries, persistence, or async execution.

## API

Implement the prepared `Practice\\JobContext` and `Practice\\JobRunner` classes.

```php
$context = new JobContext();
$runner = new JobRunner($context);

$result = $runner->run(
    ['id' => 'job-1', 'tenant_id' => 'tenant-A'],
    static function (JobContext $context): string {
        $context->set('temporary_token', 'secret');
        return $context->get('tenant_id');
    },
);

// Result: ['ok' => true, 'value' => 'tenant-A', 'error' => null]
// The injected context must now be empty.
```

### `JobContext`

- `set(string $key, mixed $value): void`: store/replace a value.
- `get(string $key, mixed $default = null): mixed`: return stored value, otherwise default.
- `clear(): void`: remove *all* values. Keys are arbitrary strings.
- Context is **instance state**, not global or static state.

### `JobRunner`

- `__construct(JobContext $context)`: use the injected context object.
- `run(array $job, callable $handler): array`: each string-keyed entry in `$job` becomes a context entry; invoke the handler exactly once with the same context instance.
- On success return **exactly** `['ok' => true, 'value' => $handlerResult, 'error' => null]`.
- On handler failure return **exactly** `['ok' => false, 'value' => null, 'error' => $originalThrowable]`. Preserve the original exception/error object. Do not rethrow ordinary handler failures.
- Clear context after every run, **including when a handler throws**. No stale fields may survive from an earlier job. A new job should start clean.
- No worker process loop is required. Calling `run()` repeatedly simulates the same long-lived worker.

## Acceptance criteria

1. Same injected context is passed to every handler; each job's own data is visible.
2. Success result preserves handler's return value.
3. Exceptions and PHP `Error` are reported as failure results, with the original throwable retained.
4. Context is empty after success, exception and Error.
5. A job after failures runs normally and cannot read stale state.
6. Previous PHP-001–005 tests still pass, including under `memory_limit=16M`.
