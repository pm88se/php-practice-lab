# PHP-007 — Dependency Graph Analyzer

- **Business scenario:** Validate task dependencies before running a workflow, import or deployment pipeline
- **PHP focus:** `SplQueue`, associative arrays, deterministic graph traversal
- **Concept:** Topological ordering using a queue (Kahn's algorithm is a useful starting point)
- **Level:** Base → Deep
- **EAV:** 25–35 minutes

## The problem

An application receives a collection of task IDs and their prerequisite IDs.
Before executing any work, it must construct a valid execution order. Tasks
whose prerequisites have not finished cannot run. Invalid references and
dependency cycles must be rejected rather than silently scheduling a subset.

Implement **one method** in `src/TaskDependencyPlanner.php`:

```php
$planner = new TaskDependencyPlanner();

$order = $planner->plan([
    'deploy' => ['build', 'test'],
    'test' => ['build'],
    'build' => [],
]);

// ['build', 'test', 'deploy']
```

## Contract

- Input: associative array `task-id => [prerequisite-id, ...]`.
  All IDs are nonempty strings in the exercise; all dependency lists are
  arrays of strings. No separate task objects or database integration.
- Output: a **list of task IDs**, containing every declared task exactly once.
- A prerequisite must appear **before** its dependent task.
- A task with no prerequisites is eligible immediately.
- Deterministic FIFO ordering: initially eligible tasks enter the ready queue in
  **input insertion order**. As processing a task makes other tasks eligible,
  enqueue newly eligible tasks in the **input insertion order of dependent
  tasks**. Already queued tasks remain ahead of newly eligible tasks.
- Duplicate references to the same prerequisite count as **one** relationship;
  e.g. `['build', 'build']` does not mean two completions are required.
- An undeclared prerequisite throws `\InvalidArgumentException`.
- A cycle (including a task depending on itself) throws `\LogicException`.
- If one disconnected component contains a cycle, reject the whole input.
- Empty input returns `[]`.
- The planner is reusable: failed invocations cannot affect later plans.

## PHP mechanism

Use **`SplQueue`** for the queue of ready tasks, not `array_shift()`.
The exercise is meant to practice the SPL queue API in a realistic workflow
context. You can use ordinary PHP arrays to represent adjacency lists,
in-degree counters and the output.

This is a **planning/validation** task, not an execution engine. No jobs,
retries, concurrency, Fibers, I/O or memory-limit optimization required.
