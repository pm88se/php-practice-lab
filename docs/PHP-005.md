# PHP-005 — Attribute-Based Event Dispatcher

- **Engineering problem:** Metadata discovery, cached Reflection, routing
- **Focus:** PHP 8 Attributes, ReflectionMethod, class-level metadata cache
- **Level:** Base → Deep
- **EAV:** 20–30 minutes
- **Setup:** `setup/PHP-005`
- **Implementation:** `drill/PHP-005` after merging setup

## Production scenario

A small CLI application has several classes with methods handling domain events. Rather than maintaining a central manual map of event names to method names, developers mark public handler methods with `#[HandlesEvent('event.name')]`.

At startup the dispatcher discovers those methods once and routes events to the **registered object instances**. Repeated event dispatch must not repeatedly scan method attributes.

This is an in-process dispatcher, **not** a durable queue, Laravel event bus, or concurrency exercise.

## Provided

`Practice\\HandlesEvent` is already implemented as a method attribute. Implement `Practice\\AttributeEventDispatcher`.

Example:

```php
final class Orders
{
    #[HandlesEvent('order.paid')]
    public function paid(array $payload): string
    {
        return 'paid:' . $payload['id'];
    }
}

$dispatcher = new AttributeEventDispatcher();
$dispatcher->register(new Orders());
echo $dispatcher->dispatch('order.paid', ['id' => 42]); // paid:42
```

## Contract

- `register(object $handler): void` scans the handler's **public** methods for `HandlesEvent` attributes and registers routing from event names to their corresponding object + method.
- `dispatch(string $event, array $payload): mixed` invokes the registered method with one argument (`$payload`) and returns its result. Unregistered event names throw `\InvalidArgumentException`.
- A class may have several annotated methods; unannotated methods are ignored.
- Exactly one handler per event name. A second attempt to register an already-owned event must throw `\LogicException` **without overwriting the previous route**.
- Cache immutable discovery results **per class name** in a dispatcher instance: e.g. event name → public method name. A second registration of the same class should reuse metadata even if the route collides. `scannedClassCount(): int` returns the number of distinct classes whose reflection metadata was built, for test observability.
- The metadata cache should store class/method information only, **not handler objects**. Runtime routes may hold registered objects strongly because they are intentionally active handlers.
- All annotated handler methods in this exercise are public, non-static, take one array argument, and have one `HandlesEvent` attribute; no signature validation or DI needed.

## Acceptance criteria

1. Discover and dispatch two differently annotated methods on one instance.
2. Support registering additional handler classes.
3. Preserve original instance (including its mutable state) when dispatching.
4. Ignore unannotated methods; throw for unknown events.
5. Reject duplicate event ownership without overwriting existing routes.
6. Dispatch should use cached routes, not repeat Reflection.
7. Re-registering a class should not rebuild the class's attribute metadata.
8. Existing tests and 16 MB memory CI remain green.

## Design hints (not a solution)

Look at `ReflectionClass::getMethods()`, `ReflectionMethod::getAttributes()` with a class-name filter, and `ReflectionAttribute::newInstance()`. Keep two different structures: **class metadata** and **live event routes**.

The provided tests intentionally fail until your implementation is added. Merge this setup PR to `main`, then make your own implementation PR.
