# PHP-002 — Lazy paid-order feed and preview

- **Engineering problem:** ENG-01 / ENG-02 — bounded-memory processing and lazy composition
- **Level:** Base → Deep
- **EAV:** 20–30 minutes
- **Your implementation PR:** from `drill/PHP-002` into `main` after this setup PR is merged

## Production scenario

The CSV import from PHP-001 currently has one consumer: order aggregation. A new operational dashboard needs a preview of the **first N paid orders** from the same export, without loading the entire file. Both consumers must use the same filtering and parsing logic.

The engineering problem is **shared lazy traversal**: the file reader should produce one matching record at a time, so aggregation can consume all records while preview can stop early.

## API to implement

Extend `Practice\\CsvOrderSummary`:

```php
/** @return \\Generator<int, array{order_id: string, amount_cents: int}> */
public static function paidOrders(string $path): \\Generator;

/** @return list<array{order_id: string, amount_cents: int}> */
public static function previewPaid(string $path, int $limit): array;
```

`paidOrders()` yields each **paid** order as:

```php
['order_id' => 'o-1', 'amount_cents' => 1299]
```

It should skip the CSV header and all non-paid orders. Keep the file traversal lazy and memory-bounded; do **not** collect all records in an array. `previewPaid()` returns at most `$limit` items from this generator and should stop iterating once the limit is reached. For `$limit <= 0`, return `[]` without processing the file.

**Refactor** the existing `summarize()` to aggregate using `paidOrders()` rather than implementing its own paid-order filtering. Preserve its existing return contract.

## Acceptance criteria

1. Generator yields the three paid orders from `orders-small.csv` in input order.
2. `previewPaid($path, 2)` returns only the first two paid records.
3. `previewPaid($path, 0)` returns `[]`.
4. `summarize()` continues to return the PHP-001 totals.
5. The existing 1,000,000-row test and all new tests pass with `memory_limit=16M`.
6. Do not change the CSV schema or add dependencies. Keep `naiveOpenCsv()` as an educational counterexample.

## Run

```bash
php -d memory_limit=16M tests/run.php
```

## Design prompts

- Where should the resource be opened and released when iteration stops early?
- What does creating a generator do compared with advancing it?
- Why is it better for aggregation and preview to share `paidOrders()` than to copy parsing logic?
- Is a generator restartable? How would a caller request another pass?

Implement in your own PR; do not add a framework or custom iterator class unless you can justify it.
