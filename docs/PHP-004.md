# PHP-004 — Weak Object Metadata Cache

- **Engineering problem:** Object lifecycle / unintended memory retention
- **Focus:** `WeakMap`, object identity, garbage collection, cache invalidation
- **Level:** Base → Deep
- **EAV:** 20–30 minutes
- **Setup branch:** `setup/PHP-004`
- **Your branch:** `drill/PHP-004` (after merging the setup)

## Production scenario

A long-lived CLI worker repeatedly handles transient request/task objects. Some downstream code needs derived metadata for each object (for example, a parsed or normalized descriptor). Computing it repeatedly is wasteful; storing it in a normal array or strong-key map risks retaining objects after tasks finish.

Build a **per-object metadata cache that must not own its keys**.

## Public API

Implement the methods in `Practice\\ObjectMetadataCache`:

```php
$cache = new ObjectMetadataCache();
$task = (object) ['id' => 42];

$metadata = $cache->get(
    $task,
    static fn (object $object): string => 'descriptor-' . $object->id,
);
$cache->has($task);     // true after get()
$cache->count();        // number of live cached objects
$cache->forget($task);  // explicit cache invalidation
```

- `get(object $object, callable $compute): mixed` calls `$compute($object)` on a cache miss, caches the result, and returns it. Repeated calls for the **same object instance** must not recompute.
- `has(object $object): bool` checks whether an entry exists.
- `forget(object $object): void` invalidates one entry; unknown objects are ignored.
- `count(): int` returns the number of currently cached object keys.
- A cached value may be `null`: distinguish an absent key from a present key whose value is `null`.
- Two separate objects with equal properties are **different** keys.

## Essential resource-lifetime behavior

An object must be eligible for collection when application code releases its final strong reference, **even while `ObjectMetadataCache` stays alive**. Once collected, its cache entry must disappear.

The tests use `WeakReference::create(...)` only to observe the lifetime of an object. Your implementation is free to choose the underlying storage, but `WeakMap` is the intended fit.

**Scope:** Cached values in this exercise are scalar/null metadata and must **not** reference their own key objects. A value holding a strong reference to the key can defeat the intended lifetime property.

## Acceptance criteria

1. Cache hit computes only once per object identity.
2. Distinct objects with the same properties are cached independently.
3. `null` is cached correctly (not mistaken for a cache miss).
4. `forget()` invalidates a single entry and is safe for absent objects.
5. Releasing the last strong reference permits garbage collection and removes the entry.
6. All existing tests, including the 16 MB resource-limited suite, keep passing.
