# PHP-011 — Stateful Multi-Source Event Processor

**Level:** Deep → Tricky  
**Focus:** Explicit generator scheduling, resume semantics, resource lifecycle  
**EAV:** 35–50 minutes

## Production context

A reconciliation worker reads three independent JSONL archives. Each has its
own filter and normalization logic:

| Source | Accepted business event | Delta |
|---|---|---|
| `payments` | `payment.settled` | `+amount_cents` |
| `refunds` | `refund.completed` | `-amount_cents` |
| `adjustments` | `ledger.adjusted` | signed `delta_cents` |

A source may also yield a control event `{"type":"source.switch","target":"refunds"}`.
The source merely reports it. It must **not** know the aggregate balance,
the state of other sources, or how the scheduler reacts.

## Task

Implement `MultiSourceEventProcessor::stream()` and `readSource()`.

- Start in `payments`.
- Read lines with `fgets()`, parse using `json_decode(..., true, 512, JSON_THROW_ON_ERROR)`.
- A source emits either a normalized business event
  `['source' => ..., 'event_id' => ..., 'delta_cents' => ...]`,
  or a control `['switch_to' => target]`.
- The outer scheduler increments its **own** balance from yielded business
  events and yields those business events to the consumer. Controls are not
  emitted to the consumer and do not change the balance.
- When a control targets a non-exhausted source, pause the current source
  and resume the target. A source must never rewind or be opened twice.
- When a source exhausts, resume the most recently paused source. Once
  there are no paused sources, the stream ends. Unvisited sources are not
  automatically processed.
- If the switch target is the current source, ignore it. If it names an
  already exhausted source, ignore it. An unknown target is an error
  (`InvalidArgumentException`).
- If switching to a source already in the paused stack, remove it from
  that stack before pushing the current source. This avoids duplicate
  entries and ensures each source has just one saved position.
- The outer generator returns the final balance through
  `Generator::getReturn()` after full traversal.
- Every successfully opened file must be closed at normal completion,
  on a parse exception, or when the entire stream is abandoned.
  **Important:** a suspended source still owns an open file. Release
  *all* suspended source generators when the orchestrator is destroyed.
- `$onOpen($path)` and `$onClose($path)` are instrumentation hooks,
  invoked exactly once when a file opens/closes. They do not perform I/O.

## What makes this harder than PHP-010?

`yield from` normally delegates until a child generator completes, but
this exercise must switch away while children are still live. Think about
`current()`, `next()`, `valid()`, source state, and ownership. This is
cooperative scheduling, **not** asynchronous file I/O.

## Acceptance

1. Inputs are processed lazily, with at most one line held per active source.
2. The event order matches switches, not file order.
3. Three simultaneous suspended sources never restart or duplicate events.
4. No double-counting across transitions; final balance is correct.
5. Unknown/expired/self switches obey the defined semantics.
6. Every opened file is eventually closed, including after early abandonment.
7. No frameworks, global caches, eager `file()` or `iterator_to_array()`
   in production code.
