# PHP-010 — Nested Generators: Delegation and Cleanup

**Level:** Deep → Tricky  
**Mode:** Implementation + lifecycle debugging  
**EAV:** 30–45 minutes

## Production scenario

A PHP CLI job processes multiple JSONL event archives in sequence. Each
archive has many lines; collecting all events at once would exhaust memory.
Only `order.paid` events are needed for a downstream revenue report.

In PHP-002 you already wrote a single lazy CSV generator. Here the challenge
is **generator composition**, propagation of completion values, and file
resource ownership when iteration is interrupted.

## API

Implement `NestedPaidEventStream::stream($paths, $onOpen, $onClose): Generator`
and the private `paidFromFile()` helper in
`src/NestedPaidEventStream.php`.

Each line is a JSON object. Yield only paid events as:

```php
['file' => 'a.jsonl', 'order_id' => 'o-1', 'amount_cents' => 1200]
```

In order of files and lines. Use `json_decode($line, true, 512,
JSON_THROW_ON_ERROR)`. The provided fixtures have valid fields, apart
from the deliberately malformed JSON line.

### Key constraints

1. **Use `yield from`** in the outer generator to delegate to each
   single-file generator.
2. `stream()` must return the total number of emitted paid events via
   `Generator::getReturn()` after full iteration. Explore how `yield from`
   provides access to the delegated generator's return value.
3. Opening a file must happen lazily, only when that file is actually read.
4. A file descriptor stays open during suspension but is closed on normal
   completion, exception, or when all references to a suspended generator
   are discarded. Use PHP `try/finally` and proper ownership.
5. Invoke the provided `$onOpen($path)` and `$onClose($path)` once per
   successfully opened/closed file. These are instrumentation hooks, not
   filesystem operations.
6. No arrays collecting the full input, `file()`, external packages,
   service processes or extra framework bootstrap.
7. Implement only these methods; all previous tests must pass.

## Test

```bash
php tests/run.php
php -d memory_limit=16M tests/run.php
```

The setup test intentionally fails until you implement both generators.

### Questions for review

- Why does a PHP generator's body not execute at creation time?
- Why doesn't `break` from a `foreach` always immediately close the file?
- What happens to `finally` when the suspended generator loses its last
  reference?
- How does `yield from` propagate emitted records, and what value does
  the expression itself evaluate to?
- Why can `getReturn()` only be called after normal completion?

**Not in scope:** asynchronous I/O, Fibers, network streams, automatic
retry, file-change detection, and general-purpose streaming frameworks.
