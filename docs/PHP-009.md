# PHP-009 — Atomic JSON Snapshot Replacement

**Focus:** PHP filesystem I/O · partial writes · rename · error cleanup  
**Type:** Implementation / Debugging  
**Level:** Base → Deep  
**EAV:** 25–35 minutes

## Business scenario

A SaaS admin panel periodically saves a small JSON configuration snapshot
that other PHP processes read directly from disk.

Today it uses `file_put_contents($path, $json)`. If the process dies or a
disk write fails halfway through, the previous valid snapshot may be
truncated or replaced by invalid JSON.

Make updates safe under the assumptions of this drill: **a local filesystem
supporting atomic same-filesystem rename (Linux/POSIX)**; one writer at a
time, readers opening the file by path.

## Your task

Implement one method in `src/AtomicJsonSnapshotWriter.php`:

```php
public function write(string $path, array $snapshot): void
```

Example:

```php
$writer->write('/tmp/current-settings.json', [
    'tenant_id' => 7,
    'features' => ['reviews' => true],
]);
```

### Contract

1. Serialize to JSON using `JSON_THROW_ON_ERROR`.
2. Never truncate or write directly to the destination path.
3. Write the **entire** serialized JSON to a uniquely named temporary file
   in the **same directory**, with basename beginning `.snapshot-`.
4. Replace the destination only after the complete successful write via
   `rename()`.
5. On any failure, throw rather than quietly returning success.
6. Remove the temporary file created by this call on failure. Never delete
   the previously valid destination.
7. Support an initial write (destination absent) and replacement (present).
8. No framework, database, Redis, shell commands, external packages, or
   helper services. Keep the code compact.

### Acceptance checks

- [ ] Initial JSON file exists and has correct data.
- [ ] Replacement contains all new data.
- [ ] A `JsonException` leaves the previous file untouched.
- [ ] Temporary files are not left behind after a successful/failed write.
- [ ] An invalid/unwritable target reports an error.
- [ ] All prior PHP-001...PHP-008 tests continue to pass.

### Verification

```bash
php tests/run.php
composer test
```

The setup PR contains an intentionally unimplemented method: tests will
fail until you solve it. Only `src/AtomicJsonSnapshotWriter.php` needs
implementation.

### Discussion for review

- Why is writing the whole JSON into a temp file safer than directly
  overwriting the final file?
- Why must the temporary file be on the same filesystem?
- Does `rename()` also guarantee durability after sudden power loss?
- Would `LOCK_EX` on the destination make direct writes atomic for readers?

**Out of scope:** multi-writer locking, crash/power-loss durability guarantees,
network filesystem semantics, Windows replacement rules and directory fsync.
These deserve separate follow-up tasks.
