# PHP-009 — WeakReference versus WeakMap: identity registry

**Type:** Debugging / Implementation  
**Level:** Deep  
**EAV:** 25–40 minutes

## Production symptom

A long-running PHP worker repeatedly resolves domain entities by **external
string IDs** (for example, `tenant:42`). The registry should return the
same object if some part of the application still holds it. But it must not
keep an entity alive merely because its ID was once requested.

A naive implementation `$entities[$id] = $entity` gradually retains
every entity ever loaded, causing memory growth.

## Task

Complete `src/WeakEntityRegistry.php`:

- `resolve(string $id, callable $factory): object`: return the alive object
  for the same ID, otherwise create an object by calling `$factory($id)`.
- `hasLive(string $id): bool`: check whether the referent is alive.
- `sweep(): int`: remove expired ID slots and return number removed.
- `slotCount(): int`: provided for diagnostics.

**Central design question:** Why is `WeakReference` appropriate for a map
with **string keys**, whereas `WeakMap` keys must be objects?

Do not solve this by retaining a normal array of strong object references.
And do not add a timeout, caching library, database, or framework.

## Required behavior

1. Resolving an ID twice while the first object is still alive must return
   the **identical instance** without invoking the factory again.
2. Resolving different IDs returns independent instances.
3. After all caller-owned strong references are removed and cycles are
   collected, `hasLive(id)` must be false.
4. A later resolve of an expired ID must invoke the factory again.
5. `sweep()` must remove only expired slots; live objects must survive.
6. Factory errors propagate; an unsuccessful factory invocation must not
   create a registry entry.
7. A cyclic object should not be artificially kept alive by the registry.
8. Previously completed PHP tests must still pass.

## Review discussion

- Why can't we directly use `WeakMap<string, object>`?
- Would `WeakMap<object, metadata>` help if the lookup starts from an ID?
- What is the difference between an expired weak reference and removing
  its string-keyed slot from the array?
- What should a caller expect if it discards the returned object and
  immediately requests the same ID again?
- What changes when the entity has a reference cycle?

This exercise intentionally introduces an identity-lifetime tradeoff, not
a syntax puzzle. Concurrent lookups, persistent storage, identity across
processes, and distributed caches are out of scope.
